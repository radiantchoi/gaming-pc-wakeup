## What was done
1. `.python-version`: `3.14` → `3.13` (matches Raspberry Pi OS trixie).
2. `pyproject.toml`:
   - `requires-python = ">=3.11"`.
   - `[[tool.uv.index]] name = "piwheels"`, `url = "https://www.piwheels.org/simple"`, `explicit = true`.
   - `[tool.uv.sources] pydantic-core = { index = "piwheels", marker = "platform_machine == 'armv6l' or platform_machine == 'armv7l'" }`.
   - Added `pydantic-core>=2.46.5` to `dependencies`.
3. `uv lock`, `uv sync` (uv downloaded CPython 3.13.14 for the dev machine).

## Deviation from plan (necessary, documented)
The plan originally kept dependencies at exactly fastapi + uvicorn. A first
`uv lock` with the source but without a direct `pydantic-core` dependency
produced a lock with `pydantic-core` sourced from PyPI only and no piwheels
entries: uv applies `tool.uv.sources` to direct dependencies only. A scratch
experiment with `pydantic-core` added as a direct dependency produced the
expected forked lock. The plan, SPEC "Package index" bullet, and minimalism
rule were updated to reflect this.
